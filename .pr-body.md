## What this changes

Delivers the phase-3 gateway prototype decided on 2026-10-15 (operator decision log,
`mcp_gateway`): a standalone MCP gateway that sits beside the xang1234 stock-screener
stack and provides a controlled, separately-authenticated MCP surface without touching
the upstream application.

### Core (passthrough + control)

- FastAPI app with `POST /mcp/`, `GET /healthz`, `GET /readyz`.
- Client auth with the gateway's **own token** (`Authorization: Bearer` or
  `x-gateway-token`, constant-time compare); the backend secret
  (`SERVER_AUTH_PASSWORD` value) stays inside the gateway process and is validated
  to differ from the client token at startup (fail fast).
- Method-level allowlist (`initialize`, `notifications/initialized`, `ping`,
  `tools/list`, `tools/call`) — everything else answered by the gateway itself
  with JSON-RPC `-32601`.
- Tool allowlist = the 13 live backend tools minus `watchlist_add` by default
  (configurable via `GATEWAY_EXCLUDED_TOOLS`); `tools/list` responses are
  filtered to that set, `tools/call` is guarded.
- Passthrough is identity-preserving (client id forwarded unchanged, notifications
  become HTTP 202). Backend outages answer with JSON-RPC `-32000` so MCP clients
  keep a protocol-consistent surface.
- `/healthz` deliberately makes **no** external call (a restarted backend must not
  flip container health — same rationale as the paperbroker phase-5 decision);
  `/readyz` does the real probes (backend `tools/list`, DB ping) and returns 503
  + reasons when degraded.

### Enrichment (the PR-#537 bridge)

- `find_candidates` responses are enriched with the **21 fields** the open upstream
  PR #537 adds to `_candidate_record`: `minervini_rating`, `canslim_rating`,
  `volume_breakthrough_rating`, `data_status`, `is_scannable`, `action_state`,
  `opportunity_state`, `vcp_detected`, `vcp_num_bases`, `volume_surge` plus the 11
  `se_*` setup-engine fields.
- Facts are read **read-only** from the stack's Postgres feature store
  (`stock_feature_daily.details_json`), never recomputed. The 11 top-level fields,
  the nested `setup_engine` object (un-prefixed keys → `se_` in projection) and the
  nested `vcp_num_bases` path were verified live on 2026-10-15 (run 20; presence
  199-200/200; `setup_engine` in 99/100 rows).
- Merged into both `structuredContent` and the `content[0].text` mirror, plus a
  `gateway` marker (`enrichment: applied|unavailable`, `fields`, `symbols_enriched`,
  `symbols_missing`). Failures never break the passthrough (fail-closed markers,
  base data intact). Other tools are untouched without a provider.

## Verification

- Local: `ruff check` clean (0.16.10, same pinning as CI) and **50/50 tests green**
  (auth, allowlist, passthrough identity, error contract, health/readiness, pure
  fact mapping incl. bool/float/negative `num_bases` guards, SQL store against a
  scripted connection, response merge + failure handling).

  and the 13-tool list were verified live against the running backend before the
  code was written; tests mirror that shape.
